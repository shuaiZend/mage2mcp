# v0.11.5 release notes

**A bulk-delisting bug, and two rules for agents that copy products.**

## The import ignored `status` and `visibility`

An import that said `status=2, visibility=1` — disabled, not visible — produced an
enabled product visible in the catalog, and the import reported success.

`status` and `visibility` are top-level product fields, not EAV attributes. They were not
in the import's reserved-column set, so they were sent as attributes; Magento ignores
unknown attributes on create, so the operator's intent was discarded silently.

The failure shape is the worst one for this bug: a planned bulk delisting becomes a bulk
listing, and nothing in the result says so. Both columns now map to the typed input on
create and update, with validation (`status` ∈ {1,2}, `visibility` ∈ 1..4), and a test
asserts the product payload carries the requested values and does not send them as
attributes.

Found by the production run on the demo store, after the money-path fixes made the import
reachable.

## The instructions now say how to copy a product

An agent copying a product from another storefront does the most damage by guessing. A
product was copied as simple when its source was configurable with two colour options; the
copy looked finished — name, price, image and category all present — and the options were
simply gone.

The initialize instructions now require:

1. **Discover before writing.** Record the source's type (simple, configurable, grouped,
   bundle, downloadable, virtual), every configurable option and dropdown with its values,
   the attribute set and the categories. Do not infer an option from a description: two
   colours can mean a configurable product, a custom-option product, or a simple product
   with colour in its title, and the three need different writes.
2. **Diff against the target** with `magento.attribute.sets`, `magento.attributes`,
   `magento.attributes.options`, `magento.category.tree` and `magento.product.media.types`.
3. **Create nothing new in the taxonomy without a human.** A new category or attribute
   changes the store for every seller and is not undone by deleting the product. The
   approval gate on a write covers the product; it does not cover the decision to invent a
   taxonomy.
4. **A copy is done when it matches** — same type, same options, same attribute values.
   Anything unreproducible is stated, not dropped.

### When the source is not Magento

Shopify, WooCommerce, a static site or a marketplace rarely maps one-to-one, and
translating field names produces a product that looks right and behaves wrong. The agent
must analyse how the source represents variants, option and attribute fields, categories,
SKUs, currency, tax class, visibility and stock, then map each concept explicitly:

| Source | Magento |
|---|---|
| A variant set | A configurable product, one child per variant |
| A text or number field | A Magento attribute, plus an attribute set that carries it |
| A flat tag list | A category tree |
| No SKUs | An invented scheme, agreed with the human |

Every uncertain mapping is confirmed with a human before writing, and again before an
update that changes an existing product's type, options or attributes. A wrong mapping is
not visible on the product page until someone tries to buy, filter or report on it.

The product.create, configurable.create and import.start descriptions carry the short form
and the one fact that decides which tool to call. `docs/mcp-tools.md` §1.1 has the
reference form.

## Testing

The rules are asserted by tests: `TestServerInstructionsRequireDiscoveryBeforeCopying`
checks ten phrases reach the client at initialize, and
`TestImportAppliesStatusAndVisibility` checks the import payload carries the requested
status and visibility and does not send them as attributes.

Full gate: `go test ./...` and `-race` clean, independent QA 18/0/0, gofmt and vet clean,
markdownlint clean.

## Upgrade notes

No configuration changes and no new dependencies.

**Behaviour change worth knowing:** an import that supplies `status` or `visibility` now
applies them. A CSV that carried those columns and relied on them being ignored will
produce different products — which is the intent, but check any saved import template.
