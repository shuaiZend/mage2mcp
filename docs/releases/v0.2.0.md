# v0.2.0 release notes

Status: **released 2026-11-19**.

## Highlights

- **Import batches**: asynchronous imports persist full batch state
  (`import_batches`, `import_batch_failures`, migration 000004), every failed row
  is stored, and `magento.import.resume` re-runs exactly those rows without the
  100-row report cap (ADR-0021). New reads: `magento.import.batches` and
  `magento.import.batch`.
- **Import retention**: the worker prunes batch history older than 30 days every
  six hours; failure rows cascade.
- **Customer management**: `magento.customer.create`, `magento.customer.update`,
  and address create/update/delete. Writes accept PII because the resource
  requires it; every response stays the PII-safe projection.
- **Bulk catalog operations**: `magento.products.bulk_update` (status,
  visibility, attributes for up to 50 SKUs with per-SKU partial-success report)
  and `magento.category.delete` (destructive, subtree removal).
- **Attribute options**: create and delete select/multiselect options, the
  values configurable variants use.
- **Media and orders**: `magento.product.media.update` (label/position/types/
  disabled) and `magento.order.cancel` (destructive, cancellable orders only).
- **End-to-end coverage** now includes bulk updates, a failing import, resume of
  the failed row, and the batch reads, in addition to the earlier write,
  configurable, order, and import flows.

## Breaking changes

None. The batch tables are additive (migration 000004); existing tools keep
their names and required fields.

## Upgrade from v0.1.0

1. Back up PostgreSQL.
2. Stop the worker, then the server.
3. Start the new server once to apply migration 000004, then the worker.
4. Verify `/healthz`, `/readyz`, `platform.info`, and one read.

No configuration changes are required.

## Verification checklist

- CI required gates, integration, docker, and the `e2e` job are green on the
  tagged commit.
- Release artifacts: 17/17 checksums match asset digests, cosign bundles and SBOM
  present, multi-arch image published.
- Post-deploy: `platform.info` reports the new version; a batch list call
  returns an empty list on a fresh database.

## Known limitations

- Batch history is pruned after 30 days; older failures cannot be resumed.
- Order creation still depends on store payment/shipping configuration and can
  leave an abandoned cart on failure.
- Configurable variant media association is not implemented yet; child product
  images are managed per SKU.
