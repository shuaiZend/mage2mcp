# v0.11.9 release notes

**Gate integrity.** The local gate had been red since 2026-11-21. Three problems were stacked so
that each hid the next, and fixing one only revealed the following one.

The record is in [`docs/audit/persona/captain-adjudication.md`](../audit/persona/captain-adjudication.md)
and [`docs/audit/lint-debt.md`](../audit/lint-debt.md).

## The stack

| Layer | Problem | What it hid |
|---|---|---|
| 1 | The skip gate counted **packages** as skipped tests | It failed every run, so nobody reached layer 2 |
| 2 | **101 lint findings** | The run stopped here, so nobody reached layer 3 |
| 3 | The test suite **raced itself** | Visible only once the first two were fixed |

`local-ci.sh` now completes end to end for the first time since it landed.

## The suite raced itself

`go test -race ./...` failed at random. Worse, `internal/storage` failed **on its own** — measured
at two failures in five runs, with a different set each time.

Two causes, both needed:

1. **Cleanup was not atomic.** The fixture deleted `operation_transitions`, then `operations`. A
   transition inserted between the two broke the foreign key.
2. **The schema name was fixed.** `test_storage` was shared by every concurrent `go test`
   process, so one run's cleanup deleted rows another was asserting on. This was the reason a
   single package failed alone: on a machine with several agents running tests, runs overlap
   constantly.

Cleanup is now a single `TRUNCATE ... CASCADE`, and each test process gets `test_storage_<pid>`,
dropped in `TestMain`. A leaked goroutine that committed a transaction after its test returned is
now joined.

**Why this matters more than a flaky test normally would:** `go test -race ./...` is the release
workflow's verify command. The previous release passing was luck. A gate that fails at random is
worse than one that fails reliably, because it teaches people to re-run until green.

Verified by repetition and by concurrency: ten consecutive race runs of the package, five of the
whole repository, and two simultaneous processes that reproduced the failure 100% before the fix
and pass after it.

## A reason nobody could read

`Escalate` has never written its `reason` argument. `cmd/worker` passes "reconciliation attempts
exhausted; manual review required" and the ledger discarded it, storing the literal token
`'escalated'` instead.

An operator looking at `operation.list{needs_attention:true}` — the view added for exactly this
purpose — learned that a row was escalated and nothing about why. The reason now lands as
`escalated: <reason>`, keeping `escalated` as the prefix of every row so existing readers keep
working, and an empty reason still lands as exactly `escalated`.

The assertion that pinned the exact string now pins the prefix and, in the same breath, that the
caller's text is really present. Loosening without strengthening would have made it decorative.

## 101 lint findings, three of them real

None were introduced by the previous release. They accumulated because `local-ci.sh` is the only
gate that runs the linter and it was failing at layer 1, so nobody reached this stage.

Most were comment format. Three were not:

- Two compared wrapped errors with `==`, which stops matching once an error is wrapped. One was
  an audit test: it silently read "no audit row" as "row present".
- Two doc comments for `JobQueue.Cancel` were attached to `PruneJobs`. The exported `Cancel` had
  no documentation at all, and its tenant-isolation rule — only the same instance and subject may
  cancel, otherwise `not_found`, so ids cannot be guessed — was written down nowhere.

Nothing was suppressed to quiet the linter. Five `nolint` directives exist, each with a specific
reason: the generators write committed documentation, so `0600` would make it unreadable; the
file paths come from fixed tables rather than user input; and the git subprocess takes literal
arguments and does not go through a shell.

**A correction worth recording:** this debt was first inventoried at 73 findings. That was wrong.
golangci-lint caps repeats at three and stops a linter at fifty, so the list was a truncated
view; measured with both caps off at the same commit, the real count is 101.

## Everything else

The skip gate no longer counts the package-level record `go test -json` emits for every package
with no test files — it had failed on every run since it landed. The failing-test extractor
matched a field order `go test -json` never produces, so a real failure printed an exit code with
no names.

`scripts/check-test-inventory.sh` fails the build when a test disappears between two refs. It
exists because twice this round a green gate was mistaken for correctness: once a test passed
while exercising a path it never entered, and once an agent rewrote a test file and wiped three
tests, leaving a file that stayed valid, compiled and passed.

## Upgrade notes

No configuration changes, no new dependencies, no behaviour change in the gateway. This release
is about the gate and about one operator-facing field.

**One behaviour change:** `operation_transitions.reason` now carries `escalated: <why>` instead of
the bare `escalated`. Existing rows keep the bare token, and `escalated` remains the prefix of
every row, so a reader that matches by prefix is unaffected.

**One operational note:** a test process killed mid-run can leave a `test_storage_<pid>` schema
behind. Normal exit drops it. This is the price of not sharing a schema with a concurrent run.
