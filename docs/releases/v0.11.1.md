# v0.11.1 release notes

**Production-readiness remediation.** A full audit of the security, Magento,
reliability, MCP, performance and documentation surfaces, with every confirmed P0
fixed and independently reviewed.

The audit record is published with the release: start at
[`docs/audit/release-readiness-report.md`](../audit/release-readiness-report.md)
for the verdict, then
[`docs/audit/known-limitations.md`](../audit/known-limitations.md) for what is
still open.

## Verdict

**CONDITIONALLY READY.** All eight confirmed P0s are fixed and independently
verified. Three limits keep it below READY:

1. **No Magento integration test.** Every Magento behaviour is verified against
   the REST contract and a fake server (`CONTRACT`), not against a live store.
2. **Order reconciliation depends on `quote_id`.** Where an instance's order
   search does not expose it, reconciliation degrades to `operation_unknown` —
   fail-safe, not automatic.
3. **Residual audit and isolation gaps** — the five self-ledgered money tools
   write their outcome audit after their own commit (`REL-16-R`); Cloudflare and
   GA4 have no outbound limits; `cmd/admin` is untested.

## Highlights

### The four unwired contracts

The audit's central finding was not a list of bugs. It was that four contracts
were declared correctly, unit-tested correctly, and never consulted by their only
real consumer:

| Contract | How it was ignored |
|---|---|
| RBAC scope ladder | `Authorize` had no scope parameter; production passed `ScopeRead` for **every** tool, so a `viewer` could call `magento.invoice.capture` |
| Retryability | `RetryableError` was called **only from tests**; the worker retried on attempt count alone |
| Confirmation binding | Bound to the argument hash but not the tool or instance — an approval for `order.hold` consumed `order.unhold` |
| Idempotency | `idempotency_keys` was dead schema; `idempotency_key_reuse` was unreachable |

All four are now enforced, each with a test proven to fail when the wiring is
reverted.

### The operation ledger

A durable record of every business mutation: `pending → executing →
{succeeded | failed | unknown}` plus `reconciling → {succeeded | failed}`, a
fencing token per attempt, an append-only transition log, and recorded-result
replay.

The rule that makes it safe: **no code path may retry an operation whose state is
`unknown`**. A retry is permitted only from `failed`, and `failed` is reachable
only when upstream proved the mutation did not apply.

### Money safety

- Capture refuses an already-paid invoice with **zero** upstream calls.
- A timeout is `unknown`, never retried, and the error is not marked retryable.
- Credit memos validate invoice linkage and refundable quantity before writing.
- Order creation keeps the cart on an ambiguous placement and reconciles on
  `quote_id`, so a foreign same-total order can no longer be attributed.
- A repeat call replays the recorded outcome instead of mutating twice.

## Upgrade checklist

### 1. Review your RBAC roles before enabling writes

Authorization now enforces each tool's declared scope. The shipped default policy
is:

| Role | Scope |
|---|---|
| `viewer`, `analyst` | read |
| `operator` | write |
| `admin` | destructive |

A deployment that relied on a read-only role invoking write tools will now be
denied. That is the fix working, not a regression.

### 2. Configure a database

Without `database.url`, confirmations and audit records are in memory, lost on
restart, and the six asynchronous import tools are not registered. The server logs
a warning; it does not refuse to start.

### 3. Check `server.max_body_bytes`

The default is now 16 MiB (was 1 MiB), so a documented 8 MiB import fits. A
write-enabled deployment below 12 MiB **fails at startup** rather than rejecting a
large import at the transport. Read-only deployments may lower it freely.

### 4. Consider per-instance limits

```yaml
datasources:
  magento:
    instances:
      - id: "store-us"
        # ...
        limits:
          requests_per_second: 50
          burst: 100
          max_concurrent: 8
```

Omitting the block keeps the default above. An explicit all-zero block means
unlimited.

### 5. Remove `public_url` from your configuration

`server.public_url` and `MAGE2MCP_PUBLIC_URL` are gone; a configuration that sets
them now fails as an unknown field.

### 6. Update calls that pass `store_id`

`magento.order.create` rejects a non-zero `store_id` with
`unsupported_capability`: the store is selected by the instance's `store_code`,
and the cart service contract takes no store id. Previously the value was silently
dropped and the order was placed in the instance's store.

### 7. Expect `instance` on the import job tools

`magento.import.status`, `.cancel`, `.resume` and `.batch` now require `instance`.
A job id is no longer a cross-tenant capability.

### 8. Run the database-backed test suite

```bash
export MAGE2MCP_TEST_DATABASE_URL='postgres://user:pass@127.0.0.1:5432/mage2mcp?sslmode=disable'
go test -count=1 -race ./...
```

Each database-backed package now uses its own schema (`test_storage`,
`test_magento`, `test_worker`), so packages no longer interfere when run in
parallel. The suite is repeatable on a non-virgin database.

## What this release is not

- It is **not** verified against a live Magento 2.4.9 store. That is the single
  largest residual risk and the reason the verdict is CONDITIONALLY READY.
- It is **not** a claim that every finding was fixed. 139 were recorded; the
  deferred ones are listed with their risk and workaround in
  [`known-limitations.md`](../audit/known-limitations.md).
- It does **not** add rate limiting for the inbound listener, Cloudflare or GA4.
