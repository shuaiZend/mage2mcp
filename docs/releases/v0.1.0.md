# v0.1.0 release notes (draft)

Status: **draft** — not tagged. The release is published from `main` through the
release workflow after maintainer approval.

## Highlights

- **Magento 2 surface**: 60+ tools across products (read, batch, search with
  price/creation filters, SEO audit, media, tier prices), configurable products
  (variant pre-checks, per-child SEO/pricing), categories, MSI inventory
  (sources, stocks, source items, assign/unassign/transfer), orders (read,
  search, status history, comments, hold/unhold, email, creation through the
  admin cart flow), invoices/shipments/credit memos (read and create, capture),
  customers (PII-safe reads and addresses), and imports (validation, bounded
  synchronous execution, asynchronous jobs with idempotency and progress).
- **SEO-aware writes**: `description`, `short_description`, `url_key`,
  `meta_title`, `meta_keywords`, and `meta_description` are typed fields with
  schema guidance (title 30-60, description 120-160, body 300+), and
  `magento.product.seo` audits them deterministically.
- **Pricing and shipping fields**: `weight`, `special_price` with its date
  window, `cost`, and `tax_class_id` on create/update and configurable children.
- **Safety**: writes require two-step human approval; arguments are validated
  against the tool schema **before** a confirmation is created; approvals are
  bound to the canonical argument hash.
- **Operations**: PostgreSQL-only job queue (ADR-0019), advisory-locked
  migrations, bounded retries, live import progress, and a repository
  end-to-end test that runs in CI.

## Breaking changes since v0.0.2

- Write calls with malformed arguments now fail with `invalid_argument` before a
  confirmation is issued. Clients that relied on receiving a confirmation for an
  invalid payload must fix the payload.
- The tool catalog status in `docs/mcp-tools.md` distinguishes implemented tools
  from the design catalog; names did not change.

## Upgrade from v0.0.2

1. Back up PostgreSQL.
2. Stop the worker, then the server.
3. Start the new server once to apply migrations (000003+), then the worker.
4. Verify `/healthz`, `/readyz`, `platform.info`, and one Magento read.

No configuration changes are required. Redis remains unnecessary.

## Verification checklist

- CI required gates and the `e2e` job are green on the tagged commit.
- Release artifacts: checksums match asset digests, cosign bundles present,
  SBOM included, multi-arch image published.
- Post-deploy: `platform.info` reports the new version; one product create
  through confirmation succeeds against a test store.

## Known limitations

- Order creation depends on store configuration (payment and shipping methods);
  a failure after the cart is created leaves an abandoned cart.
- Imports are bounded (8 MiB, 5000 rows) and non-atomic; the async job report is
  bounded to the first 100 failed rows.
- Cloudflare Logpush and GA4 BigQuery export are documented boundaries, not
  features.
- Unified analytics currently covers the traffic comparison scenario.
