# v0.11.2 release notes

**The defects the live Magento run found, fixed.** v0.11.1 shipped a
production-readiness remediation that had never been exercised against a real store.
This release runs the tool surface against one, fixes what that exposed, and closes the
remaining audit findings that did not need a design decision.

## What the live run changed

The full record is in
[`docs/audit/live-magento-test-report.md`](../audit/live-magento-test-report.md) and
[`live-magento-defects.md`](../audit/live-magento-defects.md). The three that mattered:

1. **Order placement used `POST`; Magento requires `PUT`.** The entire money path —
   order, invoice, capture, shipment, credit memo — was unreachable on a standard
   Magento 2 instance. The gateway reported it as "this store does not expose the
   cart place-order route", blaming the store for its own wrong method.
2. **A placed order could be recorded as definitely not placed.** An ambiguous
   placement whose reconciliation reads came back empty was written as
   `failed / reconciled_not_applied` while the order existed, and the caller was told it
   was safe to retry — an instruction that creates a duplicate order. Empty reads now
   prove nothing; only a surviving cart does.
3. **The reconciler's queue was never polled.** `platform:reconcile` went to the
   `maintenance` queue, which the worker's default list omitted, so 70 reconcile jobs
   sat queued on the live server and no UNKNOWN operation could ever resolve. The
   mechanism that makes an ambiguous money operation safe was inert.

## Everything else in this release

- **Security.** Upstream error text no longer reaches the agent (Magento and
  Cloudflare); `op` no longer carries identifiers; an MCP session is bound to the
  subject that created it; `/metrics` requires authentication on a non-loopback
  listener; credentials redact themselves in every formatting path; the approval CLI
  verifies the approver with the gateway's own JWT verifier and writes an audit row per
  approval.
- **Reliability.** Import batches carry a lease and are reaped when their worker dies;
  the admin token refresh is single-flight instead of holding a mutex across the HTTP
  call; the five self-ledgered money tools write their outcome audit row inside the
  ledger transaction.
- **Magento.** Products the gateway cannot make sellable are refused; addresses carry
  `region_id`; document lists page past 100 instead of truncating silently; attribute
  option ids are decoded in all three shapes Magento returns; media uploads dedupe by
  content hash and report which entry lost a role.
- **Performance.** Import existence checks are batched (10 rows: 20 requests → 11);
  import failures are written in chunks; the payload is parsed once; inventory status
  batches and bulk writes fan out under a bound.
- **API documentation.** Every required tool input and every output property carries a
  description, enforced at registration. Results carry `instance`, `tool`, `subject`
  and `request_id` in MCP `_meta` so a caller can correlate them with the log.
- **Testing.** Payloads recorded from a real store are replayed in CI; a `live`
  workflow runs the read matrix against a real store when secrets are configured;
  per-scope coverage floors are enforced.

## Verdict

**CONDITIONALLY READY**, unchanged in substance from v0.11.1 but with a materially
smaller gap. Every finding that describes a defect is closed; one performance
optimisation (`PERF-16`) remains, and closing it means trading a deterministic failure
report for latency, which is a maintainer's decision.
[`docs/audit/known-limitations.md`](../audit/known-limitations.md) has the current state.

## Upgrade notes

No new configuration keys and no new dependencies. Two behaviour changes worth knowing:

- **A viewer role can no longer call a write tool.** Authorization now enforces the
  declared scope; a deployment that relied on the old fail-open will see
  `permission_denied`. That is the fix working, not a regression.
- **`product.create` refuses `type_id: bundle` and `downloadable`.** The gateway cannot
  create their options or links, so it used to produce an enabled, visible, unsellable
  product. Create those in the admin and manage them here.

The five self-ledgered money tools now write their outcome audit row themselves; an
audit reader that assumed the middleware always wrote it should read
`docs/audit/remediation-plan.md` for REL-16.
