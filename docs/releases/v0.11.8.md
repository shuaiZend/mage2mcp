# v0.11.8 release notes

**The guidance pass.** What the server tells an agent, where it says it, and a skill so the
rules also reach clients that cannot load prompts.

Two independent reviews drove most of this: the first found that the v0.11.7 fixes were real
but incompletely delivered, the second found that the follow-up work left a pointer to a prompt
that did not exist. Both are in [`docs/audit/persona/`](../audit/persona/) with the reviews
beside the reports.

## The guidance now has a shape

The server instructions were 79 percent one task — the product-copy recipe — which left no room
for the rules that apply to every call. They are now five budgeted sections totalling **2,474
characters**, down from 3,157, and they carry what was missing entirely:

- a **write contract**: two-step approval, a different human identity, argument-hash binding,
  the derived idempotency key, and that `operation_unknown` is never retryable;
- **read semantics**: legacy inventory `qty`, what `captured` does and does not mean, that
  revenue includes canceled orders and does not deduct refunds, that `price` is the global base
  price, and that `created_at` is UTC.

The copy recipe moved out, but its resident form is a **checklist naming what to discover** —
type, every configurable option and its values, the full attribute set, the categories — plus
"create nothing in the taxonomy without human agreement". A test asserts each item so nobody can
compress it back to "discover before you write", which would leave a one-shot agent knowing it
should look without knowing what for.

## Six prompts, and a skill generated from the same text

`skills/mage2mcp/` holds the references; `scripts/gen-prompts` renders them into the server's
prompt surface. A client that loads prompts and one that reads the repository see the same
words, and a test fails when the generated file diverges.

| Prompt | Load it when |
|---|---|
| `write_contract` | about to change anything |
| `refunds` | refunding one line, or the rest |
| `reports` | reporting revenue, refunds, day buckets |
| `imports` | importing products or prices by CSV |
| `product_copy` | copying a product from another store |
| `write_safety` | writes that change catalog structure or URLs |

**Nothing to install for a client that supports prompts** — `prompts/list` returns all six.
Clients that support skills but not prompts copy `skills/mage2mcp/` into their skills directory.
[`docs/guidance.md`](../guidance.md) covers which layer applies to which client, and what is lost
when a client supports neither: the red lines still arrive, because they live in the
instructions; the step-by-step recipes do not.

## Two defects of the same shape

**A field that existed in one place and not the other.** `shipping_amount` was added to the Go
struct, but the input schema is a hand-written string with `additionalProperties: false`, and the
tool input struct and handler never carried it either. The parameter was rejected before it could
be silently dropped — and v0.11.7's release notes claimed the tool took it. All three links are
connected now, and the registration path compares every input schema against its Go struct at
startup, which immediately found the same class of bug in `magento.product.links.remove`.

**A field that was always empty.** `order.get` gained a `shipping_address` key that Magento never
returns at the top level; it lives under `extension_attributes.shipping_assignments`. The field
existed, had the right type, compiled and passed its test, and was always nil. Support still could
not confirm a delivery address after the fix that was supposed to enable exactly that. It is now
populated, with the top-level value preferred when present.

That second one forced an honesty correction: order reads **do** return shipping and billing
addresses, because support cannot confirm a delivery without them. The tool description, the
struct comment and the README all said they did not. They now say what the code does, and three
tests pin the wording.

## Everything else

Category product listing ignored `pageSize` — asking for 3 returned 182 while hydration capped at
`limit`, leaving 132 rows with an empty name; it now batches by the rows actually returned. Named
placeholders with array parameters no longer leak `%customerGroup`, and the SKU heuristic no
longer mistakes a plain number for a SKU, so a refund rejection naming an amount reaches the
caller. The local refundable ceiling accounts for adjustments already granted. `invoice_linked`
is projected at all, not merely omitted when false. `import.start` states its required columns and
that one bad row rejects the payload; `Product.Price` says it is the global base price.

## Testing

`go test ./...` and `-race` clean, QA 19 pass with no skips, the design-contract check green
(115 tools, 22 ADRs), gofmt, vet, markdownlint and the link check clean.

Two new guards, both born from defects this round:

- **`scripts/check-test-inventory.sh`** fails the build when a test disappears between two refs.
  Twice a green gate was mistaken for correctness; the second time an agent rewrote a test file
  and wiped three tests, and the file stayed valid, compiled and passed.
- **The cross-reference test asks `prompts/list`** what the server actually publishes, rather than
  trusting a hard-coded list. That is how a pointer to a non-existent prompt passed unnoticed.

## Known issues

`local-ci.sh` still fails at `golangci-lint`, which reports **71 pre-existing findings** in code
this release does not touch (17 in `operation_ledger.go`, 9 in the new `testinventory` package,
and the rest scattered). The release workflow does not run golangci-lint, so this does not block
publishing, but the local gate cannot go fully green until that debt is cleared. It is not
introduced here and it is not hidden here.

## Upgrade notes

No configuration changes and no new dependencies. The tool catalog is unchanged at 105 with
Magento enabled; the prompt surface grows from one to six.

**Behaviour worth knowing:**

1. **Order reads return addresses.** If you relied on them being absent, that was never true —
   only the documentation said so.
2. **`creditmemo.create` accepts `shipping_amount`.** Omitting it refunds no shipping on a partial
   refund; the remaining shipping returns with the last refundable units.
3. **Server instructions are shorter but stricter.** An agent that previously saw only the copy
   recipe now also receives the write contract and the read semantics.
