# v0.7.4 release notes

Status: **released 2026-11-20**.

## Highlights

- **Geography accuracy**: `magento.orders.geography` now reports
  `total_available` from Magento's `total_count`, sorts by `created_at desc` so a
  capped scan is a deterministic newest-first sample, and sets `truncated` when
  the scan cap hides orders. The first production run exposed that a 10,000-order
  cap against an 83,427-order window was reported as untruncated.
- The surface exposes **110 tools** (about 98 Magento).

## Breaking changes

None.

## Upgrade from v0.7.3

No migration or configuration change is required; replace the image and restart
the server and worker.

## Verification checklist

- CI required gates, integration, docker, and the `e2e` job are green on the
  tagged commit.
- Release artifacts: 17/17 checksums match asset digests, cosign bundles and SBOM
  present, multi-arch image published.
- Read-only production run reports `truncated: true` with `total_available`
  83,427 for the 30-day window.

## Known limitations

- The aggregate is capped at 10,000 orders per call; the report labels the sample
  size and the available total.
