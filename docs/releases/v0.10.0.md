# v0.10.0 release notes

Status: **released 2026-11-20**.

## Highlights

- **Admin-credential auto-token**: a new `admin:<username>:<password>` credential
  form mints a Magento admin bearer token, caches it, refreshes before expiry, and
  re-mints once on a 401. `bearer:` and `oauth1:` are unchanged; the security
  caveat is documented.
- **Faster CI**: docs-only changes take a fast path; Docker layers are shared
  between the docker and release-dry-run jobs; golangci-lint runs once; job-level
  concurrency and timeouts were added; a `ci-gate` job aggregates the result.
- **GitHub Actions refresh**: current majors with SHA pins retained (checkout v7,
  setup-go v7, setup-node v7, upload-artifact v7, download-artifact v8, docker
  actions, cosign-installer v4, attest v4, gh-release v3, sbom-action, scorecard,
  dependency-review v5).
- **Dependency advisory fixed**: `katex` is overridden to `^0.18.2`
  (GHSA-238p-pmpm-9mq7 / CVE-2026-103923).
- **Product copy verification**: a full Giztop→demo product copy with complete
  variants, media, categories, inventory and SEO is recorded in
  `docs/development/product-copy-run.md`, including 11 MCP defects (D1–D11) for
  follow-up.

## Breaking changes

None.

## Upgrade from v0.9.0

No migration or configuration change is required. Operators who want the admin
credential form must supply admin credentials; prefer a dedicated API-only admin.

## Verification checklist

- CI required gates, integration, docker, and the `e2e` job are green on the
  tagged commit.
- Release artifacts: 17/17 checksums match asset digests, cosign bundles and SBOM
  present, multi-arch image published.
- `npm ci && npm audit` reports no vulnerabilities; `npm ls katex` resolves
  `0.18.x`.
- actionlint and shellcheck pass on the updated workflows.

## Known limitations

- The demo product copy found 11 MCP defects (D1–D11); they are recorded, not all
  fixed in this release. The highest-impact are custom-option creation, weight
  persistence, and configurable parent stock status.
- Admin-credential tokens assume a four-hour lifetime because Magento does not
  return an expiry; shorter lifetimes are handled by the 401 re-mint.
